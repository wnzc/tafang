# 回声防线 ECHO LINE · Cocos Creator 复刻开发规格

> 本文档的唯一目标：**任何人（或任何 AI）读完这一份，就能在 Cocos Creator 里做出一个行为一模一样的《回声防线》。**
>
> 所有数值都是从原项目 `js/config.js` 等源码中**逐条提取**的真实值，不是估算。配套的 `game-data.json` 是同一份数据的机器可读版本，可直接拖进 Cocos 当配置导入。

---

## 0. 怎么用这份文档

| 你是 | 怎么读 |
|---|---|
| 人（开发者） | 按章顺序读。第 1~3 章建立心智模型，第 4~11 章是玩法与表现，第 12 章是版式与适配，第 15 章是落地映射，第 16 章是验收清单 |
| AI（代码生成） | 先读第 2 章定工程骨架与脚本划分，再从第 3 章的状态机开始写；数值一律读 `game-data.json`，**不要自己造数**；第 16 章的验收清单逐条自测 |

**三条硬约束**（违反任何一条都做不出"一模一样"）：

1. **以数据驱动为核心**：所有平衡数值集中在配置模块，逻辑代码里不许出现魔法数字。
2. **固定设计坐标系 720 宽**：所有 UI 坐标都是在"宽 720、高按屏幕比例延伸"的设计空间里写的。Cocos 里必须保留这层映射（见 2.3）。
3. **确定性更新顺序**：每帧的更新顺序固定为 `敌人 → 炮台 → 弹道 → 共振 → 波次判定 → 弹窗`（见 3.4）。顺序变了，伤害结算与手感立刻就不同。

## 1. 项目概览

### 1.1 一句话

**共振塔防**：敌人不沿固定路线走，而是每帧读流场绕开你造的塔；塔占格即变墙，玩家等于一边打一边改迷宫。核心差异化是四套机制：**动态迷宫 / 元素共振 / 地脉突变（Roguelike）/ 回响档案（局外成长）**。

### 1.2 平台与规模

| 项 | 值 |
|---|---|
| 平台 | 微信小游戏（`game.js` + `game.json`）+ 浏览器（`index.html`），一套代码双端 |
| 渲染 | 纯 Canvas 2D 立即模式，零外部资源（无图片、无字体、无音频文件） |
| 语言 | 全 ES5（原项目约束；Cocos 里改用 TypeScript，不受此限） |
| 代码量 | 18 个模块约 8290 行；其中绘制约 3339 行（render / monsters / fx / icons）、逻辑与数据约 4951 行 |
| 音效 | 23 个音色，WebAudio 实时合成 |
| 特效 | 16 类，双层合成（辉光 / 实体） |

### 1.3 四套核心机制（复刻时最先要立住的）

1. **动态迷宫**：网格上塔占位即变为不可通行；敌人用 BFS 距离场实时寻路；完全封死时敌人转入"拆塔模式"。
2. **元素共振**：七元素。相邻同元素成"链"（链内每多一座塔，全链伤害 +16%、攻速 +8%，封顶 7 座）；相邻异元素在交界处生成"反应节点"，周期性自动触发 20 对反应。
3. **地脉突变（Roguelike）**：每局开局取一个随机种子，每波开打时从**当前解锁的突变池**（起始 4 条 → 最多 8 条，见 14.1）里随机抽 1~2 条套到本波敌人（移速 / 护甲 / 血量 / 冲击 / 密度 / 回血 / 收益），同一局可复现、换种子每波都不同。双抽时倍率会往 1 收一拳（×0.65），避免两条血线相乘造成「前 18 波满血、第 19 波一波崩盘」的断崖。
4. **回响档案（局外成长）**：每局结算「回响点」，到达累计门槛即解锁内容——突变池扩容 / 冰塔「凝霜」回归 / 深渊难度档。**只解锁内容、不买数值**（详见 14.1）。

> **已下线（2026-09-19）**：主动技「共振脉冲」与核心特色「回声倒带」已从玩法移除 ——
> 风系击退 + 脉冲 + 倒带三者叠加会让难度形同虚设（一个风系节点推退全场、脉冲清屏、倒带抹掉所有失误）。
> 现在只剩「炮台 + 建造 / 升级 / 回收」一条操作线，难度由「怪海 × 血线 × 地脉突变」撑起，
> 并且**风塔击退按质量衰减**（重甲 / 巨体的退距被砍到约 1/3，脆皮小怪照常成片被吹开）。
> 第 11 章保留原设计供参考，但**不要实现**。

### 1.4 一局的完整流程

```
菜单 menu ─开始防守→ 备战 prep（12s 倒计时，可提前开波拿奖励）
    ↓ 倒计时结束或点"提前开波"
战斗 wave → 清空当前波 → 备战下一波（回到 prep）
    ↓ 第 20 波清空            ↓ 核心完整度归零
胜利 win                      失败 over
    ↓ 再来一局 → 重新开始
```

途中：新怪**第一次**出现 → 暂停 + "首次遭遇"弹窗（读完点"继续"回到原状态）。

### 1.5 术语表（后文统一用这些词）

| 术语 | 含义 |
|---|---|
| 设计坐标 | 宽 720 的逻辑坐标空间，所有 UI 数值都在这个空间里 |
| 格 / cell | 棋盘单元，64×64 设计坐标 |
| 流场 flow field | 每格到核心的最短距离（BFS），敌人朝距离更低的邻格走 |
| 共振链 link | 上下左右相邻的两座同元素塔之间的连接 |
| 反应节点 node | 上下左右相邻的两座异元素塔之间的连接点，周期性触发反应 |
| 链簇 cluster | 由链连成一片的同元素塔集合，`clusterSize` 决定增益 |
| 抑制 suppressed | 被 Boss 压制而临时脱离共振网络的塔 |
| 平砍 / 穿透 | 平砍要减护甲（最低压到 1 点）；穿透无视护甲（元素反应与持续伤害） |

## 2. Cocos Creator 工程骨架

### 2.1 建议版本与工程设置

| 项 | 建议 |
|---|---|
| 引擎 | Cocos Creator 3.8.x（TypeScript） |
| 渲染 | 2D 为主，`Canvas` 节点 + `Camera` 正交，设计分辨率 **720×1280**，`Fit Height = false`、`Fit Width = true`（横向铺满，纵向延伸，对应原项目的"720 宽、高按比例延伸"） |

### 2.3 坐标映射（关键，别跳过）

原项目的设计空间是 **宽固定 720、高动态**。`Runtime.fit()` 的作用是：

```
scale = min(720 / 逻辑宽, 设计所需高 / 逻辑高)   // 迭代收敛，见下
designH = max(逻辑高 / scale, 所需最小设计高)
ox = (逻辑宽 - 720 * scale) / 2     // 左右黑边
oy = (逻辑高 - designH * scale) / 2 // 上下黑边
屏幕坐标 → 设计坐标： (x - ox) / scale , (y - oy) / scale
```

- `所需最小设计高` 由版式模块算出（第 12 章），因为不同字号档、不同安全区下它不一样。
- 迭代最多 5 轮：`scale` 影响安全区换算、安全区影响所需高度、所需高度又反过来影响 `scale`。
- Cocos 里对应做法：根节点挂一个 `UIRoot`，把它按 `scale` 缩放、按 `ox/oy` 平移；所有子节点用设计坐标摆位。**不要用 Cocos 的 Widget/自适应去替代这套映射**，否则坐标会和本文档对不上。

### 2.4 屏幕安全区（微信）

需要读三个值，全部有官方 API：

| 值 | 微信 API | 用途 |
|---|---|---|
| 状态栏高度 `statusBarHeight` | `wx.getWindowInfo().statusBarHeight` | 整宽都要让开 |
| 胶囊矩形 `{top, height, left}` | `wx.getMenuButtonBoundingClientRect()` | 右上角避让 |
| home 条高度 | `getWindowInfo().screenHeight - safeArea.bottom` | 底部避让 |

**官方几何公式**（原项目采用）：

```
胶囊底 = 胶囊顶 + 胶囊高          // 用 top + height 推，不要只信 bottom
```

换算成设计坐标时要**同时减掉 ox / oy**（横向漏减 ox 会让右列以为自己还有位置；纵向漏减 oy 会让顶部 UI 叠到胶囊上——这是原项目实际踩过的坑）。另外：开发者工具冷启动首帧 `getMenuButtonBoundingClientRect()` 常返回全 0，需要下一帧补读一次，否则会误判成"没有胶囊"。

游戏内的避让规则（对应原项目 `buildLayout`）：

- **战斗 HUD + 棋盘 + 建造栏这一整条链**整体下移到胶囊底之下：`gameTop = 胶囊底 + 8`。
- 右列（波次/最高分/能量）默认并排缩到胶囊左侧：`hudRight = min(566, 胶囊左 - 14)`，且要求 `胶囊左 - 14 ≥ 450`；不满足（胶囊太靠左或平板）则退回 `hudRight = 566`。
- 音效开关固定挂胶囊正下方：`y = 胶囊底 + 12`，`x = 580`，`100×54`。
- 整屏页（菜单/设置/玩法/图鉴）垂直居中，**不避让胶囊**，用 `insetTop` 即可。

## 3. 全局状态与状态机

### 3.1 状态机（9 态）

| 状态 | 含义 | 跑战斗逻辑？ | 画 HUD？ | 画建造栏？ |
|---|---|---|---|---|
| `menu` | 主菜单 | 否 | 否 | 否 |
| `set` | 设置页 | 否 | 否 | 否 |
| `help` | 玩法说明页 | 否 | 否 | 否 |
| `codex` | 图鉴页 | 否 | 否 | 否 |
| `pop` | 首次遭遇弹窗（暂停中） | **否（这就是"暂停"的实现）** | 是 | 是 |
| `prep` | 备战倒计时 | 是 | 是 | 是 |
| `wave` | 战斗进行中 | 是 | 是 | 是 |
| `over` | 失败结算 | 否 | 是 | 否 |
| `win` | 胜利结算 | 否 | 是 | 否 |

另有 `prevState`（字符串）记录"从哪个状态进来的"，用于返回：设置/玩法页的返回、以及弹窗记住自己暂停在 `prep` 还是 `wave`。

### 3.2 全局状态字段（`GameState`）

```
// —— 流程 ——
state, prevState, hidden(切后台), time(秒，永不暂停，驱动所有动画)

// —— 数值 ——
coreHp, coreMax(=100), energy, score, kills, leaked, wave, wavesTotal(=20)

// —— 实体 ——
enemies: Enemy[], towers: Tower[], bullets: Bullet[]

// —— 波次 ——
waveData: WavePlan|null, spawnIdx, waveTime, prepT

// —— 回声 ——
echo(0~100), echoBuffT, snaps: Snapshot[], snapT

// —— 交互 ——
sel: Tower|null(选中的塔), selCard: TowerKey|null(选中的卡), pulseMode: boolean

// —— 表现 ——
shake, redFlash, whiteFlash, hitStop, toastMsg, toastT, bannerMsg, bannerT

// —— 存档与图鉴 ——
best, codexTab(0怪1塔), codexSel, codexQueue: string[], popKey: string|null
```

### 3.3 初始化

| 时机 | 动作 |
|---|---|
| 游戏启动 | 读设置 → 读存档最高分 → 重置状态 → 初始化 UI → 绑定输入 → 起主循环 → 绑定前后台暂停 |
| 重开一局（`reset()`） | 状态回 `menu`、时间归零、核心/能量/分数/波次全部复位、清空三个实体数组、清特效与共振、重置网格并重建流场、`best` 从存档读 |
| 开始防守（`startRun()`） | `state='prep'`、`prepT=12`、横幅"备战 · 第 1 波"2.2 秒、提示"点下方卡片选塔 → 点棋盘空格建造"4.5 秒 |

**注意**：`reset()` 清 `codexSel / codexQueue / popKey`，但**不清图鉴解锁记录**——那是跨局的。

### 3.4 每帧更新顺序（不可改）

```
1. if (hidden) return                       // 切后台：整帧跳过，时间也不走
2. time += dt                               // 先推进全局时间（弹窗里动画照常跑，靠的就是这句）
3. 衰减：shake / redFlash / whiteFlash / toastT / bannerT
4. FX.update(dt)                            // 特效不参与伤害，先更新
5. if (state ∈ {menu,set,help,codex,pop,over,win}) return   // ← 弹窗的"暂停"全在这一行
6. if (state == 'prep') { prepT -= dt; if (prepT<=0) startWave(false) }
7. if (state == 'wave') 按 waveTime 刷怪（同帧可刷多只，上限 72 只）
8. Enemies.update  →  Towers.update  →  Bullets.update  →  Resonance.update
9. 若选中的塔已被移除，清空 sel
10. if (state=='wave' && spawnIdx>=events.length && enemies.length==0) waveComplete()
11. if (codexQueue 非空 && !popKey && state ∈ {prep,wave}) openPop()
```

> 早先这里还有第 10 步「回声快照」（每 0.15 秒存一份战场状态）——随倒带一起下线了。
> 现行 11 步顺序里不再有任何"记录过去"的环节。

两条容易漏的细节：

- **`time` 在早退之前就加了**，所以弹窗/图鉴里怪物形象仍在做动画——一个完全静止的弹窗看起来像卡死。
- **弹窗的开启放在本帧所有战斗逻辑之后**（第 12 步）。这样"暂停"落在完整帧边界上，而不是半帧里；否则刚生成、还在出生线外的怪会停在屏幕外不动。

### 3.5 主循环与 dt 处理

```
step(ts):
  if (hidden) { last = ts; 排下一帧; return }        // 后台期间不更新不重绘，但把时钟对齐
  dt = (ts - last) / 1000 ; last = ts
  if (dt > 0.06) dt = 0.06                            // 掉帧保护
  if (dt < 0) dt = 0
  if (hitStop > 0) { hitStop -= dt; dt *= 0.22 }      // 顿帧：只在重击/漏怪/倒带时短暂触发
  update(dt); render()
```

**顿帧刻意放在主循环而不是 `update` 里**，这样无头逻辑模拟用固定步长时完全不受影响。

**切后台**：`hidden = true` 并挂起音频；回前台 `hidden = false`、恢复音频、若在 `prep/wave` 给一条"已暂停 · 已继续"横幅 1.3 秒。不做需要点击的遮罩。

## 4. 地图与棋盘

### 4.1 网格参数

| 项 | 值 | 说明 |
|---|---|---|
| `CELL` | 64 | 格边长（设计坐标） |
| `COLS × ROWS` | 10 × 13 | 棋盘格数 |
| `BX` | 40 | 棋盘左上角 x |
| `BOARD_W` | 640 | = 10 × 64 |
| `BOARD_H` | 832 | = 13 × 64 |
| `boardY` | 动态 | 由版式算：HUD 之下、建造栏之上，见 12.5 |
| `CORE_CELLS` | `[[4,12],[5,12]]` | 核心占两格（底行中央），是寻路终点 |
| `SPAWN_COLS` | `[0, 9]` | 两个出生列（第 -1 行） |

**棋盘宽 832 是定值，缩格子会动平衡**——不要在 Cocos 里为了适配而改 `CELL`，要缩就整体缩放。

格坐标 ↔ 世界坐标：

```
cellCX(c) = BX + (c + 0.5) * CELL
cellCY(r) = boardY + (r + 0.5) * CELL
worldToCell(x,y) = { col: floor((x - BX)/CELL), row: floor((y - boardY)/CELL) }
```

### 4.2 流场（本作与传统塔防最大的差异点）

维护 **三张** 距离场，都是 `Int32Array(COLS*ROWS)`，值 = 到源点的最短步数，`-1` = 不可达：

| 流场 | 源点 | 允许穿越塔格？ | 用途 |
|---|---|---|---|
| `flow` | 核心两格 | 否 | 常规寻路 |
| `phaseFlow` | 核心两格 | **是** | 相位体穿墙期寻路 |
| `towerFlow` | 所有塔所在格 | 否 | 拆塔模式/无路可走时找最近的塔 |

**BFS 算法**（4 邻，不用 8 邻算距离）：

```
build(sources, passBlocked):
  f = 全部 -1
  queue = []
  对每个源点 s：若在界内且 f[s] == -1 → f[s] = 0，入队
  while queue 非空：
    cur = 出队；d = f[cur]
    for 每个四邻 (nc, nr)：
      越界 → 跳过
      f[ni] != -1 → 跳过            // 已访问
      !passBlocked && blocked[ni] → 跳过
      f[ni] = d + 1 ; 入队
  return f
```

**重建时机**：塔数组发生任何变化（建造/回收/被摧毁/倒带还原）后立刻 `recompute`：

```
blocked[] ← 全部清零，再把每座塔的格子置 1
flow      = build(核心格, false)
phaseFlow = build(核心格, true)
towerFlow = 塔数量为 0 ? null : build(塔所在格, false)
```

### 4.3 可建造判定

一格可建 ⟺ 在界内 **且** 不是核心格 **且** 未被占用。

### 4.4 棋盘绘制（从下到上）

1. **底盘**：圆角矩形 `(BX-9, boardY-9, BOARD_W+18, BOARD_H+18, r=20)`，填充 `#182840`，描边 `rgba(150,190,255,0.18)`，线宽 1.5。
2. **格子**：每格内缩 2px 画圆角矩形 `r=8`，颜色按 `(row+col)%2` 交替：`#20324f` / `#25395a`。
3. **出怪口**：在两个 `SPAWN_COLS` 列、`boardY+26` 处画尖朝下的三角形（半径 14、3 边、旋转 90°），填充 `#ff5d6c`，透明度 `0.35 + 0.4 * (0.5+0.5*sin(t*3 + 列序号*2))` —— 呼吸闪烁。
4. **核心**：覆盖 `CORE_CELLS` 两格合并的区域，内缩 6px 圆角矩形 `r=14`，线性渐变填充（`rgba(69,214,255,0.30)` → `rgba(80,110,255,0.18)`），描边 `rgba(120,230,255, 0.5+0.5*pulse)` 线宽 2.5，`pulse = 0.5+0.5*sin(t*2.4)`。
   中心再画：半径 `20 + pulse*5` 的圆环描边（`rgba(180,240,255,…)` 线宽 2）+ 半径 16、4 边的菱形填充。上方 `-48` 处居中写"核心"（13 号字，`rgba(180,240,255,0.8)`）。
5. ~~**脉冲瞄准提示**~~：**已下线**（`pulseMode` 不再存在，棋盘不再有瞄准框）。

### 4.5 绘制顺序（整屏）

```
底色渐变 → 底色冷光晕 → [震屏平移] 棋盘 → 塔 → 共振链 → 反应节点 → 敌人 → 弹道 → 特效
→ 顶部 HUD → 底部建造栏 → 塔面板 → 横幅 → 提示 → 受击红晕 → 白闪 → 整屏版式/弹窗 → 音效开关
```

两条必须遵守的顺序：

- **链画在塔之上**。相邻塔只隔 64px，链画在下层会被塔身整段盖住，而"哪里成链了"是玩家最需要一眼看懂的信息。
- **反应节点也画在塔之上**（同理，否则被塔身挡住）。

底色是**竖向渐变**：`#0f1b2f → #182840 (45%) → #0f1b2f`，再叠一层中心在 `(360, designH*0.34)`、半径 `designH*0.78` 的极淡冷光（峰值 `rgba(122,172,255,0.11)`）——纯色底在手机上会显得又平又闷，且容易和塔身、怪物糊成一片。

### 5.2 实体字段

```
uid(自增)  key  def(数值引用)  color  r
col, row(逻辑格；出生时 row=-1)  x, y(世界坐标)
speed(基础速度)  maxHp  hp  armor  dmg  reward
alive  mode('path' | 'chew')  target(啃的目标塔)
// 状态计时器
slowT, slowAmt   superT(易伤)   stunT(定身)   burnT, burnDps
phaseT, phaseCd  hitFlash
// 击退速度场
kbvx, kbvy, kbT, kbImmune
// 表现
reactT, reactName, reactColor   fx, fy(行进方向)   off(侧向偏移 -15..15)
spawnT(出生缩放倒计时，初值 0.35)   _flip(朝向镜像)
```

**初始值**：`slowT/slowAmt/superT/stunT/burnT=0`；相位体 `phaseCd = phaseCycle * 0.6`（一进场就先空转 60%，不会立刻相位）；`spawnT = 0.35`。

### 5.3 行进逻辑（每帧，分子顺序不可换）

```
1. 计时器衰减：spawnT / hitFlash / reactT / kbImmune / slowT(归零时 slowAmt=0)
   / superT / stunT
2. 燃烧结算：burnT -= dt；hp -= burnDps * dt；hp<=0 → 走统一死亡结算
3. 相位：phaseCd -= dt；<=0 → phaseT = phaseDur, phaseCd = phaseCycle
         phaseT > 0 → phaseT -= dt，标记 phasing = true
4. speed = 基础速度 * (1 - slowAmt) * (1 + buff)
   frozen = (stunT > 0)
   buff = 0                             // 倒带后遗症已下线（echoBuffT 不再存在）
5. 出生保护：if (y < boardY - 2) { if (!frozen) y += speed*dt; continue }
6. 击退位移（独立于寻路，定身期间照样被吹）
7. if (!frozen && kbT <= 0)：
     破墙者分支（见 5.5） 或 常规寻路（见 5.4）
8. 抵达核心判定：所在格是核心格 → leak(e)，从数组移除
```

### 5.4 寻路 `steer`（每次只走一格）

```
r = floor((y - boardY)/CELL) ; c = floor((x - BX)/CELL)

若 r < 0 或无流场：          // 还没进棋盘
   c = clamp(c, 0, COLS-1)
   目标 = (BX + (c+0.5)*CELL, boardY + 0.5*CELL)
否则：
   在 8 邻里找 f 值最小且 >= 0 的格；对角移动时要求两个正交邻格都不被阻挡（禁穿角）
   若没有更低值（或没有合法邻格）→ 原地不动，目标 = 当前格
   目标 = 该格中心

// 侧向偏移：让怪流呈带状而不是一条直线
dir = normalize(目标 - 自身)
goal = 目标 + 垂直方向 * off        // off 是 -15..15 的随机数，出生时定死
朝 goal 前进 min(d, speed*dt)，并记录 fx/fy 为实际行进方向
```

### 5.5 拆塔模式

`mode = 'chew'`，`target` = 最近的塔。触发条件二选一：

1. **破墙者**：`def.towerDps` 存在且不在相位中 → 永远优先找塔（`towerRange = 74`）。
2. **其他怪**：所在格流场值 `< 0`（无路可走）→ 找 74 半径内最近的塔。

咬合结算：

```
if (塔.shieldT > 0)  // 结晶护盾：啃不动，怪被顶住原地磨（护盾的意义就在这）
else {
  塔.hp -= dps * dt        // 破墙者用 def.towerDps(=13)，无路可走的怪固定 13
  塔.hitFlash = 0.2
  塔.hp <= 0 → destroyTower(塔)
}
```

### 5.6 击退：速度场，不是瞬移

| 常量 | 值 | 含义 |
|---|---|---|
| `KB_TAU` | 0.20 s | 速度衰减时间常数 |
| `KB_IMMUNE` | 0.55 s | 两次击退之间的最短间隔 |

**为什么不用瞬移**：早期版本是"命中瞬间 `x -= dir * push`"，叠上减速时最难看——怪被瞬移推回去，下一帧又沿流场挪回来，两帧之间位置突变，观感"一卡一卡"。

施加一次击退：

```
push(e, dirX, dirY, dist):
  if (!alive || dist <= 0) return false
  if (kbImmune > 0) return false              // 免疫窗
  if (y < boardY) return false                // 还在出生通道，不吃击退
  if (slowAmt > 0) dist *= (1 - 0.55 * slowAmt)   // 减速中的怪击退距离缩水
  v0 = dist / KB_TAU
  (kbvx, kbvy) = -normalize(dir) * v0         // 沿行进**反**方向
  kbT = KB_TAU * 3.5                          // 到 3.5τ 速度只剩 3%
  kbImmune = KB_IMMUNE
```

每帧位移：

```
kdt = min(dt, 0.05)                           // 防掉帧时一步跨过衰减窗口变成瞬移
x += kbvx * kdt ; y += kbvy * kdt
decay = exp(-kdt / KB_TAU) ; (kbvx, kbvy) *= decay
夹在棋盘内：x ∈ [BX+6, BX+BOARD_W-6]，y >= boardY+6，越界的轴向速度清零
```

**三个配套约束缺一个就重新变难看**：

1. 击退期间**不前进**（跳过 `steer`）——否则前进与后退同时生效，净位移趋近 0，怪在原地抖。
2. `kbImmune` 让同一只怪最短 0.55s 才被推第二次——多个反应节点同帧命中时，击退不会叠成一次超长位移。
3. 位移夹在棋盘内——被吹回出生区会重新走"出生保护"分支，看起来像"被吹上去卡住了"。

### 5.7 伤害结算（唯一入口）

```
damageEnemy(e, amt, color, opts?):
  if (!e.alive) return
  dmg = opts.pierce ? amt : amt - e.armor
  if (dmg < 1) dmg = 1
  if (e.superT > 0) dmg *= (1 + 0.25)         // 超导易伤
  e.hp -= dmg ; e.hitFlash = 0.12

  // 飘字：小伤害不飘（塔一多会糊屏），只有 >= 26 才报数
  if (dmg >= 26 && e.hp > 0) 飘字(round(dmg))

  if (e.hp <= 0):
     e.alive = false ; kills++ ; energy += reward ; score += reward * 2
     echo = min(100, echo + 3)
     boss ? 大爆炸(半径150/白闪/震屏14/顿帧0.1/白屏0.55) : 普通爆炸
  else: 命中音
```

**反应伤害（`pierce: true`）与持续伤害（燃烧/毒域）一律无视护甲**——这是高护甲怪唯一的解法，也是"第 5 波那只 Boss 怎么打"的答案。

### 5.8 漏怪与胜负

```
leak(e):
  coreHp -= e.dmg ; leaked++ ; 震屏 9 ; 红闪 0.6 ; 顿帧 0.06
  爆炸特效 + 飘字 "−{dmg} 核心" + 漏怪音 + 重震动
  if (coreHp <= 0) → state = 'over'（红闪 1、白闪 0.7、记最高分）

win(): state='win'，白闪 0.8，记最高分
```

## 6. 怪物 UI（十一只怪的矢量画法）

### 6.1 为什么是矢量画而不是图片

原项目三条理由，复刻时同样成立：

1. 小游戏加载图片必须异步，渲染层要处理"图还没到"的中间态；矢量绘制是同步的。
2. 动画要**逐部件**——腿在摆、尾巴在甩、锤子在抡、大嘴在开合。一张静态图只能整体平移缩放。
3. 任意尺寸都清晰：卡片、棋盘、弹窗只是同一个函数传不同的半径。

### 6.2 单位空间约定（**复刻的关键**）

- 每只怪都在"单位空间"里作画，**身体半径固定为 `UNIT = 14` 单位**；绘制时整体缩放 `k = r / UNIT`。
- 于是同一份代码，小怪（r=11）与 Boss（r=27）都自动对版。
- 取 14 而不是 16 是量出来的：形象四角（耳朵、角、锤子）会伸到 ±16 单位，按 14 缩放正好占满 r 的格子；按 16 缩会小一圈，棋盘上看着"没长开"。
- 纵向统一压在 `y ∈ [-18, +16]` 单位内。
- **形象外扩上限**（`MON_EXTENT`，实测值）：`up 1.44r` / `down 1.31r` / `side 1.36r`。弹窗与血条排布都靠这三个数，别自己估。

### 6.3 通用配色（由怪物主色派生）

```
c  = 主色（受击时 tint 到 78% 白）
d  = shade(c, -0.40)   // 暗部（触须、后腿、脚）
l  = shade(c, +0.52)   // 亮部（高光、信号灯、发光球）
INK = '#0a1020'        // 统一描边色（比背景深一点，边缘才不脏）
BLUSH = 'rgba(255,124,166,0.45)'
WOOD = '#c99a5f'   STEEL = '#c3cede'
```

`shade(hex, amt)`：`amt < 0` 时按 `1+amt` 比例压暗；`amt > 0` 时按比例往白里混。
`tint(hex, t)`：t=0 原色、t=1 纯白（受击白闪用 `t = 0.78`）。

### 6.4 通用零件（先实现这 10 个基元，十一只怪都是它们的组合）

| 零件 | 作用 |
|---|---|
| `oval(x,y,rx,ry)` | 椭圆，用 4 段贝塞尔画（不依赖 `ctx.ellipse`，老基础库没有） |
| `dome(x,y,rx,ry)` | 上半椭圆、底边闭合（头盔 / 壳 / 幽灵头顶） |
| `jelly(rx,ry)` | 果冻身：上圆下分瓣 |
| `ghostBody(wav)` | 幽灵身：圆顶 + 三段波浪下摆 |
| `limb(x1,y1,x2,y2,w,col)` | 粗肢体：先画 `w+3.2` 宽深色描边，再压本色（描边卡通质感） |
| `foot(x,y,rx,ry,col)` | 小圆脚掌 |
| `ground(y,rx,ry,sc)` | 地面投影：`globalAlpha = 0.26*sc` 的黑色椭圆，每只怪脚底高度不同（见 `SHADOW_Y`） |
| `eye(x,y,r,lx,ly,closed)` | 眼睛：白眼球 + 追着行进方向的瞳孔（偏移 ≤ 0.34r）+ 高光；closed 时画闭眼弧 |

**眨眼**用 seed 错开，避免全场同时闭眼：

```
blinkAt(t, sd):  p = (t*0.62 + sd*0.41 + 1.3) % 3.7 ; return p < 0.1
sd = off * 0.13 + (uid % 13) * 0.47
```

### 6.6 对外接口与朝向


```
draw(ctx, e, t, sc):
  k = e.r / UNIT ; 无形象或 k<=0 → 返回 false（调用方画圆点兜底）
  主色 = tint(e.color, hitFlash>0 ? 0.78 : 0)
  lx, ly = normalize(e.fx, e.fy)        // 无方向时默认朝下 (0,1)
  sd = e.off*0.13 + (e.uid % 13) * 0.47
  P = { c, d, l, fl, lx, ly, blink, phasing, st(=mode), alpha }
  // 朝向：朝左走就镜像，留 0.12 死区避免来回抖
  if (e.fx < -0.12) _flip = 1 ; else if (e.fx > 0.12) _flip = 0
  translate(e.x, e.y) ; scale(k*sc) ; if (_flip) scale(-1, 1) ; art(P, t, sd, sc)
```

`sc` 是出生缩放：`spawnT > 0` 期间从 `0.2` 线性长到 `1.0`（`lerp(0.2, 1, 1 - spawnT/0.35)`）。

### 6.7 在 Cocos 里怎么落地

三条可行路线，按推荐度排：

1. **`Graphics` 组件 + 每帧重绘**（最贴近原实现）。把上面 10 个基元函数照抄成画 `Graphics` 的工具（`moveTo/bezierCurveTo/lineTo/close/fill/stroke`），怪物形象代码几乎可以 1:1 翻译。缺点是节点数少时 drawcall 低但 `Graphics` 重建有 CPU 开销——原项目是立即模式，习惯就在这。
2. **预渲染成 `SpriteFrame`**：十一只怪 × 若干动画关键帧烘焙成图集，运行时只做翻转变换。性能最好，但失去逐部件连续动画，且要额外做一套导出管线。
3. **Spine / DragonBones**：适合有条件做骨骼精修的情况，但需要重新绑定美术。

**推荐路线 1**，理由：本文档给出的每一处动画都是"部件旋转/位移 + 相位函数"，翻译成 `Graphics` 重绘是最短路径；且 `eye` 的瞳孔追视、`blink` 的 seed 错开、`_flip` 镜像这些细节都依赖代码而不是资源。

**形象改动的验收守则**：任何改动都不得让视觉外扩超出 `MON_EXTENT`（up 1.44 / down 1.31 / side 1.36），否则会顶到血条或压住邻格。

### 7.1 上场阵容（6 座）

卡片栏顺序由 `TOWER_ORDER` 决定：`['pyro','hydro','dendro','anemo','electro','geo']`，
**只有这 6 张**（脉冲 / 倒带卡片已随主动技一起下线），按 `ceil(n/2)` 铺两行 3+3，卡宽 221。

| key | 名称 | 元素 | 造价 | 耐久 | 伤害 | 射程 | 攻速(次/秒) | 攻击方式 kind | 附加参数 |
|---|---|---|---|---|---|---|---|---|---|
| `pyro` | 炎爆 | 火 | 60 | 260 | 17 | 152 | 1.15 | `bolt` | 弹速 460，寿命 1.6s |
| `hydro` | 澄流 | 水 | 65 | 260 | 9 | 168 | 0.95 | `wave` | 范围 56，减速 30%，持续 1.4s |
| `dendro` | 青蔓 | 草 | 75 | 250 | 11 | 150 | 0.62 | `spore` | 范围 52，灼烧 14/秒，持续 3.2s |
| `anemo` | 流风 | 风 | 80 | 240 | 7 | 138 | 0.80 | `gust` | 范围 96，击退 18px × 质量系数（见下） |
| `electro` | 掣雷 | 雷 | 90 | 240 | 24 | 192 | 0.70 | `chain` | 跳 3 次，跳距 132 |
| `geo` | 磐岩 | 岩 | 100 | 340 | 52 | 148 | 0.42 | `spike` | 定身 0.45s |

> **击退质量衰减（2026-09-19 加）**：实际退距 = 击退值 ÷ `mass`，
> `mass = 1 + (r - 10) * 0.09 + armor * 0.18`。
> 代入：游荡体 1.27（几乎照吹）、群涌体 ≈ 1.0（完全照吹）、装甲体 2.35（约 4 折）、Boss 3.25（约 3 折）。
> 这是「风系不再一吹全退」的核心 —— 脆皮小怪照常被成片吹开（割草爽点保留），
> 重甲 / 巨体只能被轻轻顶一下，逼玩家改用元素反应（无视护甲）和重击塔去磨。
> 注意它还和减速耦合：被减速的怪吃到的击退再 × `(1 - 0.55 * slowAmt)`，避免「慢 + 退」把怪钉死在原地。

**冰塔「凝霜」不是常驻阵容，而是「回响档案」的第一条解锁奖励**（见 14.1）。
它的完整参数：造价 85 / 耐久 260 / 伤害 10 / 射程 164 / 攻速 0.85 / 范围 58 / 减速 50% / 持续 2.0s / 冻结概率 22% / 冻结 1.1s。

三条实现约束：

1. **上架与否由 `TOWER_ORDER` 决定**（不是靠 `CFG.TOWERS` 里有没有 `cryo`）。
   `CFG.TOWERS.cryo` 一直存在、`ELEM.cryo`、5 条冰系反应、图标、音色也一直都在——
   所以它「回归」是零美术零逻辑成本的，只是别把它放进上架表。
2. **累计 1300 回响点**解锁；在此之前卡片只有 6 张（两行 3+3），解锁后 7 张（两行 4+3）。
   卡片布局是自适应的（`perRow = ceil(n/2)`），但**版式自检的卡片断言与坐标锁必须同步**。
3. 若复刻时选择跳过成长系统，请把 `cryo` **常态化上架**（那会变成 7 座塔的版本），
   而不是让它消失——它是完整设计的一部分，只是为了给成长系统留一条「看得见的奖励」才暂时锁上。

### 7.2 等级成长

```
伤害 = 基础伤害 * (1 + 0.32 * (等级-1)) * dmgMul
射程 = 基础射程 * (1 + 0.06 * (等级-1))
攻速 = 基础攻速 * (1 + 0.12 * (等级-1)) * rateMul
耐久 = 基础耐久 * (1 + 0.35 * (等级-1))
```

| 操作 | 花费 | 效果 |
|---|---|---|
| 升级（Lv1→5） | `round(基础造价 * 0.85 * 当前等级)` | 等级 +1，血量回满 |
| 满级后再点 | `round(基础造价 * 0.5)` | 维修：血量回满（满级且满血时提示"已达最高等级"） |
| 回收 | 返还 `round(累计投入 * 0.7)` | 移除塔并重算流场与共振 |

`累计投入 spent` 初始 = 造价，升级/维修都累加进去。

`dmgMul / rateMul` 由共振链提供；被 Boss 压制时额外 `dmg *= 0.85, rate *= 0.85`；`quickT > 0`（激化）时 `dmg *= 1.3`。

### 7.3 索敌

优先级 = **流场距离最小的敌人**（即最靠近核心的那只），距离相同时取离塔更近的。

```
pickTarget(塔, 射程):
  遍历所有 alive 且 spawnT <= 0 的敌人
  超出射程² → 跳过
  v = flow[敌人所在格]
  if (v < 0) v = 9000 + d²*1e-6      // 不可达/在棋盘外的敌人排最后
  取 v 最小；v 相同取 d² 更小
```

### 7.4 开火

每帧：

```
for 每座塔:
  计时器衰减：hitFlash / flash / recoil(速度 7.5/秒) / shieldT / quickT
  cool -= dt ; if (cool > 0) continue
  st = stats(塔) ; target = pickTarget(塔, st.range)
  if (!target) { cool = 0.05; continue }        // 没目标时每 50ms 重试一次
  cool = 1 / max(0.1, st.rate)
  shoot(塔, st, target)
```

`shoot` 公共部分：

```
ang = atan2(target.y - t.y, target.x - t.x) ; 塔.angle = ang
塔.flash = 0.12 ; 塔.recoil = 1
炮口坐标 = 塔 + (cos(ang), sin(ang)) * 29        // 与炮管管口圆心对齐，用未后坐的位置
FX.muzzle(炮口, ang, 24, 元素色) ; Audio.shoot(elem)
```

#### 六种攻击方式

**① `bolt` 直射弹（炎爆）**
生成子弹：`{x,y = 炮口, speed:460, life:1.6, dmg, elem, r:4.2, color:元素soft}`，沿飞行方向溅射火花。

子弹每帧（`updateBullets`）：

```
life -= dt
目标存在且活着 → 朝目标当前位置飞；否则朝最后记录的位置飞（target = null）
记录上一帧位置 px/py（渲染层靠它拉拖尾）
距离 <= 步长 + 目标半径 → 命中：damageEnemy(target, dmg) + 按飞行方向溅射火花，销毁
否则前进 step；若 life <= 0 → 销毁
```

**② `wave` 范围减速波（澄流）**
从炮口到落点画一道冷光 `beam`，落点炸开 `ring(8 → aoe)`，再按元素派发（冰用 `ice`，其他用 `ember`）。
然后对范围内所有敌人（`dist <= aoe + e.r`）：

```
damageEnemy(e, dmg)
e.slowAmt = max(e.slowAmt, 0.30) ; e.slowT = max(e.slowT, 1.4)
if (def.freezeChance && rand < freezeChance) { e.stunT = max(..., freezeT) ; FX.ice }
```

**③ `chain` 连锁闪电（掣雷）**
从炮口起，在目标与"最近的未命中目标"之间连跳，共 `chain = 3` 跳：

```
from = 炮口 ; cur = target
for i in 0..2:
  命中集合加入 cur
  i == 0 → FX.bolt(粗电弧) ; else → FX.arc(细电弧)
  damageEnemy(cur, dmg)
  from = cur的位置 ; cur = 上一个命中点 chainRange(=132) 内最近的未命中敌人
```

**④ `gust` 龙卷推开（流风）**
落点 `ring(10 → aoe=96)` + 爆发粒子；对范围内敌人：

```
damageEnemy(e, dmg)
Enemies.push(e, e.fx, e.fy, def.push=18)     // 沿行进反方向推开 18px，分帧走完
```

**⑤ `spike` 重击单体（磐岩）**
只打单体：`FX.shock(34)` + 碎晶，`damageEnemy(target, dmg)`，`target.stunT = max(..., 0.45)`。

**⑥ `spore` 落孢毒域（青蔓）**
落点 `ring(8 → aoe=52)` + 余烬；对范围内敌人：

```
damageEnemy(e, dmg)
e.burnT = max(e.burnT, 3.2) ; e.burnDps = max(e.burnDps, 14)
```

灼烧在 `Enemies.update` 里每帧结算，**无视护甲**。

### 9.2 共振链（同元素抱团）

**建链条件**：上下左右相邻、两个塔元素相同且都未被压制。

**成簇**：把所有这些边连成无向图，DFS 求连通分量，每个分量就是一个簇。

**增益**（对簇内每座塔）：

```
size = min(簇内塔数, chainCap = 7)
dmgMul  = 1 + 0.16 * (size - 1)
rateMul = 1 + 0.08 * (size - 1)
clusterSize = size
```

即 7 座同元素塔抱团 → 伤害 ×1.96、攻速 ×1.48。

链的**视觉**（三层，全部画在塔之上）：

1. 底层柔光：`lighter` 混合，元素色 `alpha 0.16`，线宽 9。
2. 中层流动虚线：`setLineDash([9,13])`，元素色 `alpha 0.72` 线宽 3，`lineDashOffset = -(t*26)%22`。
3. 上层能量光点：`lighter`，每条链 3 个点沿链流动，相位 `(t*0.9 + k/3 + i*0.17) % 1`；半径 3.6 的元素色点 + 1.7 的白色内点；`alpha = (0.42 + 0.12*(size-1)) * sin(相位*π)`——**链越长越亮**。

### 9.3 反应节点（异元素贴边）

**成节点条件**：上下左右相邻、两个塔元素不同、二者都未被压制。

- 节点 key = 两个塔 uid 排序后拼接（`min-max`），保证同一个几何位置只产生一个节点。
- 反应定义按**元素名字母序**拼 key 查表：`kk = (e1 < e2 ? e1+'|'+e2 : e2+'|'+e1)`。
- 节点圆心 = 两塔位置的**中点**。
- **初始冷却 = `cd * 0.3`**（不是满 cd，贴上去很快就能看到第一次触发）。
- 重建时**保留已有节点的剩余冷却**（按 key 匹配）：否则每 0.22 秒重建一次，冷却会被无限重置，反应永远打不出来。

**重建节流**：`Resonance.update` 每 `0.22` 秒重建一次全网络（链 + 节点），而不是每帧。建造/升级/回收/倒带时额外立即重建一次。

## 10. 波次编制与经济

> 这一章是 **roguelike 化之后**的版本：每局的敌群与「地脉突变」由 `(seed, 波次)`
> 决定（同一局可复现、换种子每波都不同），怪量已拉到「爽游怪海」的档位。

### 10.1 难度曲线

```
hpMul     = 1 + 0.245*(n-1) + 0.0099*(n-1)²     // n = 第几波
rewardMul = 1 + 0.10*(n-1)
isBoss    = (n % 5 === 0)
base      = round((16 + floor(n * 2.8)) * mut.spawnMul)   // 本波主怪数量
```

| 波次 | hpMul | 说明 |
|---|---|---|
| 1 | 1.00 | |
| 5 | 2.14 | Boss 波 |
| 10 | 4.01 | |
| 15 | 6.37 | |
| 20 | 9.23 | 终局 Boss 波（深渊档再 ×1.35 = 12.46） |

**这条曲线是阈值型的**，标定时务必用固定种子扫一串样本，不要只看单局：

- `0.30/0.014`（≈11.7 倍）：旧值，后期「打不动」（游荡体 62 血变 1052，第 5 波 Boss 4448 血，
  而玩家那时只有四五座一级塔、合计不到 60 秒伤）。
- `0.22/0.008`（≈8.1 倍）：太松，理想 AI 满血通关。
- **`0.245/0.0099`（≈9.2 倍）：现行值**，理想 AI 会掉肉但守得住。
- `0.26/0.011`（≈9.9 倍）：太狠 —— 会出现「第 19 波漏 14 只、核心 100→16，第 20 波 Boss 收尾即崩」
  的断崖，连理想 AI 都在最后一波被打破。

**深渊档**（见 14.1）：在 `hpMul` 之上再乘 `CFG.DEEP.hpMul`（1.35），收益乘 `rewardMul`（1.15）作补偿。
两条乘法只在 `deep` 为真时执行，常规路径一个数都不变。

### 10.2 每波的怪物池与编队

**11 种怪按波次解锁**（`waves.js` 的 `UNLOCK`）：

```
UNLOCK = { drifter:1, sprinter:2, swarmling:3, bulwark:4, wraith:5,
           sunder:6, titan:7, phaser:8, tinker:9, mender:10 }
pool = 所有满足 UNLOCK[k] <= n 的 key

mainType = pool[floor(rnd() * pool.length)]     // 主力（随机！不再按波次轮转）
subType  = pool[floor(rnd() * pool.length)]     // 副队

heavyK = HEAVY_K[mainType] || 1                 // 肉盾作为主力时减量
HEAVY_K = { titan: 0.42, bulwark: 0.70 }
c1 = ceil(base * 0.62 * heavyK) ; c2 = base - c1
主力：c1 只，出现时间 0.3 + i*0.34，出生列交替 spawn = i % 2
副队：c2 只，出现时间 2.4 + i*0.30，出生列固定 0
```

**为什么肉盾要减量**：某个种子第 19 波抽到巨岩体当主力，138 只里约 86 只是巨岩体
（每只 300 基础血 × 8.6 倍血、还带护甲），20 秒一波内根本清不掉——那不是「难」，
是组合本身无解。肉盾的正确形态是「少量硬点 + 大量杂兵」，所以减量后**差额落到副怪**，
总怪量不变、割草的密度感一点不丢。

**Boss 波额外规则**：`n % 5 === 0` 时在最前面（1.6s）插一只 Boss，`hpMul * 0.88 * mut.hpMul`，
出生列 `n % 2`；同时主怪数量 `base = max(4, round(base * 0.62))`。

**破墙者小队**：`n >= 6 && n % 3 === 0` 时，追加 `1 + floor(n/10)` 只破墙者（`hpMul * 0.85`），
出现时间 `6 + i*1.1`，出生列固定 1。只在部分波次出现，避免跨波次累积。

**群涌体成群**：`n >= 3` 时每波额外成团压上——`swGroups = 3 + floor(n/3)` 组（第 20 波约 10 组），
每组 `5 + floor(rnd()*5)` 只（5~9 只）。这是「割草」主视觉的来源，配合 AOE 塔形成清屏快感。

最后把所有事件按时间排序。`waveName` = Boss 波取「共鸣吞噬者」，否则取主力怪名。
同帧刷怪上限 **72 只**（超过就跳过本帧这一次生成）。

### 10.3 地脉突变（Roguelike 层）

每波开打时从**当前可用池**里抽 1~2 条突变，套用到该波全部敌人：

```
池子 = CFG.MUTATIONS.slice(0, N)     // N 由「地脉谱系」解锁线的档位决定：4 → 6 → 8
mutCount = 1 + (rnd() < 0.3 ? 1 : 0)
muts = pickSome(池子, mutCount, rnd)   // 不重复抽样，顺序不影响概率
```

| # | key | 名称 | 效果 | 池位 |
|---|---|---|---|---|
| 1 | `swift` | 疾风地脉 | 移速 ×1.22 | 起始池 |
| 2 | `regrowth` | 回响地脉 | 每秒回血 8 | 起始池 |
| 3 | `eclipse` | 蚀影地脉 | 击杀收益 ×0.75 | 起始池 |
| 4 | `frenzy` | 狂乱地脉 | 移速 ×1.14、冲击 ×1.25 | 起始池 |
| 5 | `ironhide` | 铁甲地脉 | 护甲 +4、血量 ×1.10 | 解锁池 |
| 6 | `bloodfury` | 血怒地脉 | 血量 ×1.22、冲击 ×1.30 | 解锁池 |
| 7 | `swarm` | 涌动地脉 | 生成量 ×1.5 | 解锁池 |
| 8 | `titanfall` | 巨力地脉 | 血量 ×1.35、护甲 +2 | 解锁池 |

**数组顺序就是解锁顺序**（取前 N 条），所以排在前面必须是**最温和**的几条：
新玩家起步只遇到它们，解锁后再把硬货放进来——这是「增加变数」而不是「单纯变难」，
也是 roguelike 的正统做法。早先按数值类型排，结果起始池是疾风/铁甲/涌动/血怒——
四条里三条硬加难度（涌动更是怪量 ×1.5），与意图正好相反。

**双抽温和化**：连抽两条时，把每条的倍率往 1 折 0.65（`1 + (x-1)*0.65`，护甲则 `×0.65`）。
不加这条，`巨力 1.35 × 血怒 1.22` 再乘后期血线能到 14 倍，出现「前 18 波满血、
第 19 波一波漏 12 只直接崩盘」的断崖。

### 10.4 能量经济

| 来源 | 数额 |
|---|---|
| 开局 | 320（够多铺一座 AOE 塔，割草更顺） |
| 击杀 | `round(基础赏金 * rewardMul * mut.rewardMul)`（注意蚀影地脉会打折） |
| 清空一波 | `60 + 波次 * 12` |
| 提前开波 | `floor(剩余备战秒数 * 3) + 25` |
| 回收塔 | `round(累计投入 * 0.7)` |

**分数**：击杀 `赏金 * 2`；清空一波 `60 + 波次 * 20`。

**备战**：每波开始前 **9 秒**倒计时；倒计时归零自动开波；玩家可点「提前开波」立刻开始并拿奖励。
开波时播放冲击波 + 音效 + 横幅「第 N 波 · {波名}」2.2 秒。

**Boss 波额外提示**：「Boss 来袭：元素反应无视护甲｜别把塔贴在它的行进路线上」（`|` 是手动换行符）。

### 10.5 胜负

- **胜利**：清空第 20 波（`wave >= 20` 时 `waveComplete` 直接转 `win`）。
- **失败**：核心完整度归零。
- 两者都结算回响点（见 14.1）；只有**常规档**刷新最高分 `echo_best`——
  深渊局的分数天然更高，混进去会把常规榜弄脏，它记在档案的 `deepBest`。

### 11.2 回声倒带（核心特色）

**充能与快照**

| 项 | 值 |
|---|---|
| `echo` 上限 | 100 |
| 击杀 + | 3 |
| 清空一波 + | 22 |
| 回退窗口 | 4.0 秒 |
| 快照间隔 | 0.15 秒（最多保留 `ceil(4.0/0.15) = 27` 份，超出丢最旧） |

**快照内容**：

```
{ core(核心血量), energy, score,
  towers: [{ key, col, row, level, hp, spent }],
  enemies: [{ uid, key, x, y, hp, maxHp, reward,
              slowT, slowAmt, superT, stunT, burnT, burnDps,
              phaseT, phaseCd, kbvx, kbvy, kbT, kbImmune,
              alive, off, mode }] }
```

**击退速度必须一起进快照**：不回退的话，倒带后怪会带着"未来的推力"继续滑，而快照里它的位置还是旧的——两者对不上就是凭空位移。

**执行倒带**（需 `echo >= 100` 且有快照）：

```
取最早的一份快照，清空快照队列，重置 snapT
还原 coreHp / energy / score
塔：按快照重建（保留 level，hp 夹到新的 maxHp，spent 还原）；重算流场
敌人：按 uid 尽量复用现有实体（避免重新 spawn 的动画），否则用 rebuild 重建；逐字段 restore；清空子弹
后遗症：echoBuffT = 5.0 秒（敌人移速 +18%）
清空交互状态：echo = 0，sel / selCard / pulseMode 全清，重建共振
视觉：向内收束的时间环（冲击波 300 + 190，圆环 620 + 420，30 束火花 + 8 粒环绕余烬）
震屏 13 + 白闪 0.45 + 顿帧 0.08 + 横幅"回声倒带 · 时间回退 4 秒"1.8 秒 + 音效 + 重震动
```

充能不足时提示"回声充能不足 {N}%"，无快照时提示"无可回溯的记录"。

## 12. HUD 与版式

### 12.1 设计坐标与字号三档

**所有 UI 数值都在 720 宽的设计空间里**。字号有 3 档，每档 = 两条同源曲线的同一次取值：

### 12.4 底部建造栏

```
gap = S(8) ; rowGap = S(8) ; cardPadTop = S(10) ; cardH = S(104)

perRow = Math.ceil(nCard / 2)                 // 3
nRow   = Math.ceil(nCard / perRow)            // 2
barH   = cardPadTop*2 + cardH*nRow + rowGap*(nRow-1)   // 两行 → 236
barY   = designH - insetBottom - barH
cw     = Math.floor((696 - S(8)*2 - (perRow-1)*gap) / perRow)   // → 221
```

### 12.5 棋盘定位

```
contentTop = max(268, 开波按钮底边 + S(14))          // HUD 之下留呼吸位
gameNeed   = contentTop + 832 + barH + insetBottom
RESERVE_BELOW = S(78)                                // 给浮动提示留的落脚位

面板 `(48, popTop, 624, S(800))`；遮罩 `rgba(10,18,32,0.80)`（**刻意留一点透，让玩家看到战场还在，只是停了**）。

形象圆心与半径由"上躲定位行、下躲概括行"的剩余空隙取中点算出：

```
r = S(56)
top = 面板.y + S(142) + FS(13)/2 + S(8)
bot = 面板.y + S(356) - FS(13)/2 - S(8)
y   = round((top + 1.44*r + bot - 1.31*r) / 2)     // 1.44 / 1.31 = MON_EXTENT 的 up / down

`r = 56` 是"塞得下的最大值"，再大最高的那只怪就会顶到定位行。

### 14.1 回响档案（局外成长）

**设计原则：只解锁内容，不买数值。** 这是硬约束不是偏好——本作难度是阈值型的，
上一节那条曲线动 6% 就能让 20 波从「掉肉能过」变成「最后一波被打穿」。
任何**永久数值加成**只要超过约 3% 的输出增量，就会让整条曲线塌掉；
而 Roguelike 与永久成长天生打架（永久变强会毁掉「每局平等」）。
业界标准解法是「解锁广度、不买深度」（像《以撒的结合》：解锁新道具进池子，不给永久攻击力）。

**存档结构**（`echo_profile`，纯对象、可 JSON 化）：

```
{ pts, runs, kills, wins, best, deepBest, deep }
```

**读存档一律当不可信输入**：缺字段补默认、数值防 NaN/负数/无穷。
老存档（少字段）必须能正常加载，新字段自动拿默认值。

**回响点结算公式**（每局结束，**失败也给点** —— roguelike 最劝退的就是「打不过=一无所获」）：

```
回响点 = 波次 × 12 + ⌊击杀 ÷ 8⌋ − 漏怪 × 15 + (通关 ? 200 : 0)
```

通关满 20 波约 665 点，打到第 10 波崩掉约 135 点。结果钳到 ≥ 0（不出负分）。

**三条解锁线，累计门槛制（不是消费制）**：

| 线 | 门槛 | 解锁内容 |
|---|---|---|
| 地脉谱系 | 1000 / 3000 | 突变池 4 → 6 → 8 条（见 10.3） |
| 凝霜回归 | 1300 | 冰塔「凝霜」重新上架建造栏 |
| 深渊 | 3800 | 血量 ×1.35 档，独立最高分 `deepBest` |

**为什么是累计制而不是商店**：点数只累计、到门槛自动解锁，玩家不需要决定「花在哪」——
省掉一整个商店 UI（本作界面已经很满），也没有「点错浪费」的懊恼。
全部解锁约 6~8 局，门槛数值需按真实手感校准。

**凝霜回归的两个实现要点**：

1. 塔表拆成两层：`TOWER_ORDER_ALL`（全部 7 座，固定）与 `TOWER_ORDER`（**当前上架**）。
   卡片、建造、图鉴、版式全部只读 `TOWER_ORDER`；改它的**只有 profile 一处**。
   这样「上架与否」的判断不会散落到渲染与输入里。
2. 卡片布局是**自适应**的（`perRow = ceil(n/2)`），所以 6 座 → 7 座会自动变成两行 4+3、
   卡宽 221→164，建造栏高度不变——布局代码几乎不用改，但**版式自检的卡片断言与坐标锁要跟着更新**。

**深渊档**：开局按存档定、局中不改（中途切换会让前后波次不同档，排行榜也没法解释）。
玩家在档案页开关，**下一局生效**。

**UI 落点**（三处，都是纯增量）：

- **档案页 = 图鉴页的第三个 tab**（`codexTab == 2`）。这样复用 `CODEX_H`(1000)，
  **不进 `pageNeed = max(MENU_H, SET_H, HELP_H, OVER_H, CODEX_H, POP_H)`**，
  全局 `designH` 与那几十条结构断言一条都不用动。
  （若另开新页，高度必须压到 `HELP_H`(1150) 以内，否则全局缩放基准会漂移。）
- **菜单入口**：`UI.menuSubBtns()` 是表驱动，`drawMenu` 与 `onTap` 读同一张表，加一个入口只改 ui.js 一处。
  四个入口（玩法/图鉴/回响/设置）按 `subBtn(i)` 等距排布。
- **结算页**：数据行加一行「本局回响点」（六行、行距 44）；「本局新解锁」**改写副标题**而不是新增行
  （副标题与首行数据之间只有 `S(52)`，塞第三行字在大字号档下必挤——S 与 F 两条曲线不同源）。

**验证方式**：`tools/simulate.js` 的存档桩读空档案（＝新玩家）。
带 `--deep` 时会先塞一份满解锁档案，于是能跑到「7 座塔 + 8 条突变池 + 深渊倍率」这条路径；
它会断言 `game.deep` 与 `TOWER_ORDER` 确实生效，否则直接判失败。
