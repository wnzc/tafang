# 回声防线 · ECHO LINE

一个**故意不像传统塔防**的微信小游戏。纯 Canvas 2D 绘制，无任何外部图片/音频资源，整个包体就是 JS。

---

## 一、它哪里不一样

| 传统塔防 | 回声防线 |
|---|---|
| 敌人沿固定路线走，塔只管输出 | **塔会占格变成墙，敌人用流场实时重算路线绕开你** —— 你其实是在边打边造迷宫 |
| 把路堵死就赢了 | 完全封死时，敌人会**转身直接拆你的塔** |
| 塔之间毫无关系，堆满就行 | **元素共振**：同元素相邻成链加伤，异元素相邻在交界处触发**元素反应**（蒸发 / 融化 / 超载 / 感电 / 超导 / 冻结 / 扩散 / 结晶 / 绽放 / 激化 / 燃烧） |
| 漏怪只能干看着 | **回声倒带**：充能满可让整个战场回退 4 秒（含已漏掉的怪、已花掉的钱） |
| 塔只能升级 | 额外有**主动技「共振脉冲」**：手动点地板放范围伤害＋眩晕 |
| 只有静态贴图 | **22 种程序化合成音效 + 16 类特效**：爆闪、冲击波、分叉电弧、冰晶、顿帧、屏幕暗角 |
| 说明书式的新手引导 | **新怪首次出场直接把战斗停住弹脸**（形象 + 四维 + 要点），见过就不再打断；首页**图鉴**能回看已遭遇的怪（没见过的画三个问号）与六座塔的全部元素反应 |

### 1. 会绕路的敌人（动态迷宫）

地图上没有预置路径。每当你落下一座塔，全场的 BFS 流场立刻重算，
所有敌人的行进方向当帧改变。

- 入口在左上 / 右上，核心在正下方正中（两格宽）。
- 敌人沿「到核心的 BFS 距离场」逐格下降，支持斜向走位但禁止穿墙角。
- 若流场显示**完全不可达**，敌人自动切换为「拆塔模式」，奔向最近的塔并造成持续伤害。
- 因此龟缩封路不是必胜策略，而是一场「用空间换时间」的赌博。

### 2. 元素共振（本作核心玩法）

元素共七种：**火 / 水 / 冰 / 雷 / 风 / 岩 / 草**（当前上场六种 —— 冰塔「凝霜」暂时下线，
见本节末尾的留档说明），元素图标是内置的矢量路径数据
（`js/icons.js`，只有几百行路径数据，不是图片）。

**同元素相邻 → 共振链**
链内每座塔都获得加成：链长 n 时伤害 ×(1+0.16(n−1))、攻速 ×(1+0.08(n−1))（n 封顶 7）。
链在视觉上表现为塔之间流动的虚线。

**异元素相邻 → 反应节点**
在两塔交界处生成一个自动触发的节点，有独立冷却环。**七元素两两组合共 20 对，
除「草 + 冰」外各有对应反应**（标 ※ 的需冰塔，当前打不出来）：

| 反应 | 组合 | 效果 |
|---|---|---|
| 蒸发 | 火 + 水 | 白热汽爆，高额范围伤害 + 击退 |
| 融化 ※ | 火 + 冰 | **全表最高单发**范围伤害 |
| 超载 | 火 + 雷 | 爆炸 + 电弧跳射 4 次 |
| 感电 | 水 + 雷 | 连锁闪电在怪群间跳 5 次 |
| 超导 ※ | 冰 + 雷 | 范围伤害 + 易伤（承受伤害 +25%） |
| 冻结 ※ | 水 + 冰 | 范围定身 |
| 扩散 | 风 + 任意 | 元素被"扯出去"，中范围伤害 + 强击退 |
| 结晶 | 岩 + 任意 | 给邻塔上护盾，5 秒内免疫啃咬 |
| 绽放 | 草 + 水 | 草原核炸开，二段伤害 |
| 激化 | 草 + 雷 | 邻塔伤害临时 +30% |
| 燃烧 | 草 + 火 | 范围内敌人持续掉血（DoT） |

> 这就是本作的解题核心：**想拉满伤害要同元素抱团，想吃到反应又必须让异元素贴边。**
> 两种需求互相拉扯，摆位本身成了策略。
>
> 当前 6 座炮塔各对应一种元素，攻击方式也各有分工：火直射 / 水减速波 / 草落孢毒域 /
> 风龙卷推离 / 雷连锁 / 岩重击定身。

#### 冰塔「凝霜」留档说明

标 ※ 的三条反应（融化 / 超导 / 冻结）需要冰塔才会触发，当前版本打不出来。冰塔本身也已下线，
原因是它和水塔同为 `kind:'wave'`（范围减速波），职能重叠最高；收掉一座正好把建造栏从
9 张卡变成 8 张（两行 4+4，卡宽 129 → 164，元素图标才看得清）。

**留档的东西一样没少**：`CFG.TOWERS.cryo` 的定义（注释块）、`CFG.ELEM.cryo` 的配色、
5 条 `cryo|*` 反应的参数、`js/icons.js` 里的冰元素图标、`towers.js` 的冻结概率分支、
`audio.js` 的 `shootFrost` 派发。**恢复 = 解开 `CFG.TOWERS` 里的注释块 + 把 `'cryo'`
加回 `CFG.TOWER_ORDER`，两处一起解即完全生效**（建造栏会自动回到 5+4 两行）。

### 3. 回声倒带

每 0.15 秒对全场（敌人位置与血量、塔的等级与耐久、能量、分数）做一次快照，环形缓冲保留 4 秒。
充能满 100% 时点击「回声倒带」，整个战场回溯 4 秒 —— 包括**已经漏掉的怪会被拉回来重新走一遍**。

代价是：回声清空，并且所有敌人获得 +18% 移速持续 5 秒（"适应"）。

#### 六只怪都是手绘形象 + 逐部件动画（`js/monsters.js`）

不是几何色块，也不是图片 —— 是**用 canvas 路径现画的矢量角色**，每只都按名字设计，
每个部件（腿、尾巴、锤子、嘴）各有一套随时间走的动画：

| 单位 | 形象 | 动画 |
|---|---|---|
| 游荡体 | 果冻水母 | 上下浮动、四条触须摆动、呼吸压扁、独眼追视、眨眼、天线球发光 |
| 疾行体 | 小走兽 | 前倾猛跑、双腿反摆、耳朵后压、尾巴甩、身后速度线 |
| 装甲体 | 厚壳小坦克 | 沉重左右摇摆、双脚交替抬、壳檐一排铆钉、信号灯呼吸、观察缝里眨眼 |
| 破墙者 | 戴安全帽抡锤 | 啃塔时 8Hz 大力抡锤（平时扛着轻晃）、怒眉、咬牙 |
| 相位体 | 小幽灵 | 波浪下摆飘、手臂轻摆、相位时错位重影、身后残影 |
| 共鸣吞噬者 | 大嘴怪 | 呼吸缩放、大嘴开合（牙齿跟着开合）、共鸣角脉动、双臂张开 |

另外每只怪共用一套：**出生缩放、受击白闪、朝左走自动镜像、脚下地面投影、瞳孔追着行进方向看**。

为什么不用图片：① 小游戏加载图片必须异步（`wx.createImage` + `onload`），渲染层要处理
"图还没到"的中间态，这个工程从第一行起就是零外部资源、同步绘制；
② 静态图只能整体平移缩放，做不出"腿在摆、锤子在抡、嘴在开合"；
③ 矢量放到多大都清晰，卡片、棋盘、结算页共用同一个函数。

形象的尺寸约定：**单位空间里身体半径 14 单位，绘制时按 `r / 14` 缩放**，
所以「怪占几格」仍是 `CFG.ENEMIES[key].r` 说了算（不影响射程与命中判定），
形象只是把这块地占满。**改形象要守三条线**：顶边不能进血条区间（`e.y - r - 13` 往上）、
半宽不能超过 `1.4r`（否则压到邻格）、外扩不能超过 `CFG.MON_EXTENT` 的登记值（弹窗按它排布）——
这三条分别由 `layout-check.js` 的「怪物形象不顶血条 / 不横向溢出 / 实测外扩不超出登记值」
断言自动挡下，不用靠肉眼。`CFG.MON_EXTENT` 本身也是量出来的（记账 ctx 把每只怪按 12 个
动画相位各画一遍算包围盒取最大），不是估的：最高的游荡体到 `1.44r`，按 `1.0r` 排弹窗会压住定位行。

#### 首页图鉴页 + 「首次遭遇」弹窗（`js/codex.js`）

**图鉴**：首页三个次级按钮中间那个「图鉴」进去，两个 Tab：

| Tab | 内容 |
|---|---|
| 怪物 | 3×2 网格。见过的画形象 + 名字 + 定位；**没见过的画一个大问号 + 「???」+「未遭遇」** |
| 炮台 | 3×2 网格，六座塔的元素图标（内置矢量路径）+ 名字 + 「造价 · 攻击方式」 |

点任意一格进详情：怪物给「四维数值 + 特性要点」，炮台给「四维数值 + 攻击方式 + **该元素参与的全部元素反应**」。
反应那一栏是现算的（`Codex.reactionsOf(elem)`）：每条反应列出对手元素图标、反应名、**折算成人类可读的效果**
（"92 范围 9 · 易伤 +25% 3.2s"）、以及右端的「× 对手塔名」。**冰塔留档期间，涉及冰的各条会显示成灰色的「未上线」**
—— 不是漏了，是这条反应现在真的打不出来。

**首次遭遇弹窗**：每只怪**第一次**出场时，战斗立刻停住，弹出这只怪的档案（形象 + 四维 + 要点）。
出现过的怪不再打断 —— 记录存在 `echo_seen`（微信 `getStorageSync` / 浏览器 `localStorage`），
读回来会按 `CFG.ENEMIES` 过滤一遍，删过的怪不会留下永远解不开的幽灵格。

两个实现细节值得记下来：

- **「暂停」是 update 早退，不是停掉时钟**。`main.js` 在 `codex` / `pop` 状态直接 return，所以
  `waveTime`、出怪、塔的开火全停；但 `game.time` 照常走 —— 于是**弹窗里的怪还在做动画**。
  要是连时钟一起停，弹窗会是一张静止的画，看起来像卡死。
- **同帧刷出两只新怪就排两个弹窗**（`codexQueue`），关掉第一个自动弹第二个，全关完才回到
  `prevState`（只认 `prep` / `wave`）继续打。弹窗与图鉴的几何全部来自 `G.UI.codex*` / `G.UI.pop*`，
  渲染和命中判定读同一份坐标，不存在「看得到点不到」。

### 5. 音效与特效

**音效全部是实时合成的**，一个音频文件都没有，所以包体不会变大。

- 每个音效 = 若干个振荡器 + 一段滤波噪声，现场叠加包络（`js/audio.js`）。
- 三个关键工程点：
  1. **节流**：命中音 48ms、开火音 140ms 内最多 3 声。塔一多就必然重叠，不做预算会变成白噪音。
  2. **压缩器**：主输出挂 `DynamicsCompressor`，几十路音同时响也不会削顶爆音。
  3. **渐进降级**：浏览器走 `AudioContext`（需首次点击解锁），小游戏走 `wx.createWebAudioContext()`；
     两者都不可用时静默无声，绝不影响游戏逻辑。
- 右上角有音效开关，状态存本地，任何界面都能点。

**响度链路**（`master → compressor → makeup → destination`）：

调整音量时最容易踩的坑是把压缩器阈值压得太低。原来的 `-16dB / 9:1` 会把**单个音头也一起削掉**，
听感上不是"变稳"而是整体发闷、变小。现在只拦真正的峰值：

| 参数 | 值 | 说明 |
|---|---|---|
| `MASTER_VOL` | 0.85 | 送进压缩器之前的电平，也是静音开关的目标值 |
| 压缩器阈值 / 比 | -10dB / 5:1 | 只压峰值，不碰正常音头 |
| `MAKEUP_VOL` | 1.30 | 压缩之后再补回来 |

整体响度比调整前高约 2.5 倍（单音头从 ~0.165 提到 ~0.42）。**要整体调响或调轻，只动那两个常数**，
`audio-selftest.html` 里有断言锁住它们，改小会被自检挡下。

**特效分两个绘制层**（`js/fx.js`）：

- `glow` 层用 `lighter` 叠加混合 → 冲击波、电弧、光束、爆闪、炮口闪光
- `solid` 层用常规混合 → 粒子、碎片、余烬、飘字

每帧只切换两次合成模式，所以哪怕同时几百个特效也不掉帧。特效总量有 1100 的上限，
超出会丢弃最旧的一批（实测高负载峰值约 300）。

**炮塔视觉**：六边形底盘 + 可见的**冷却环**（走完一圈就是一次开火，节奏一眼看清）、
伸到底盘外的炮管、开火后坐、**塔身核心画该元素的图标**（元素身份一眼可辨，不再靠自创符号猜）、
**等级越高越华丽**（Lv2 内环 → Lv3 六角饰钻 → Lv4 双旋环 → Lv5 光晕 + 环绕晶石，逐级叠加）、
被 Boss 压制时跳短路电弧、共振链外环随链长发光。

**底部建造栏**：8 张卡（6 塔 + 脉冲 + 倒带）**分两行 4+4 平铺**，末行不足时整行居中。
冰塔还在时是 9 张、两行 5+4，卡宽被棋盘总宽锁死只有 129；冰塔下线后卡宽涨到 164，
元素图标的细节（`elemIcon` 里那条矢量路径）才真正看得清。

### 6. 微信安全区适配（状态栏 / 胶囊 / home 指示条）

小游戏里 canvas 是**铺满全屏**的，状态栏、右上角胶囊、home 指示条都浮在它上面：
画上去的内容会被盖住，**胶囊还会吞掉那块区域的点击**。所以这三个区域必须主动让开。

适配的真值来自两个 API，缺一不可：

| 来源 | 用途 |
|---|---|
| `wx.getWindowInfo().statusBarHeight` | 顶部整宽留白（时间 / 信号那条） |
| `wx.getWindowInfo().safeArea` | 底部 home 指示条留白 |
| `wx.getMenuButtonBoundingClientRect()` | **胶囊的精确矩形**。不能猜，各机型差别很大 |

三个设计决定：

1. **战斗 HUD 整条链下移到胶囊下方**。状态栏整宽留白后，战斗 HUD（左列标题 / 血条 +
   右列波次 / 能量）+ 棋盘 + 建造栏这一整条链整体下移到胶囊底之下，把右上角胶囊那一行
   完整让给系统 UI；标题落在内容区左上角（胶囊下方左侧）。整屏版式（菜单 / 设置 / 玩法 /
   图鉴）垂直居中即可，不避让胶囊。浏览器下没有胶囊，`gameTop` 退回状态栏高度，逐像素不变。
2. **右列仍"并排缩到胶囊左侧"（横向避让）**。整体下移后，右列顶边已随 HUD 落到胶囊之下，
   但水平方向仍要把右沿缩到胶囊左侧（左沿留 14 设计 px 余量 → 方案 A），避免压到胶囊；
   横向挤不下时整列并排（方案 B）。
3. **音效开关挂在胶囊正下方**。那块是天然空档，且离系统按钮最近，手感最顺。

> 整体下移是主动取舍：把 HUD 顶从状态栏下推到胶囊底，会额外吃掉约 66 设计坐标的顶部空间，
> 短屏机型整体缩放再缩约 5~8%。版式自检的「安全区缩放损失」护栏因此从 5% 放宽到 12%
> （见 `tools/layout-check.js` 第 10 条）。真机短屏本就有黑边，影响有限。

HUD 在微信下按 **0.86** 纵向压缩（浏览器保持 1.0，逐像素不变），把省下的高度还给棋盘。
`0.86` 是量出来的：再紧标题与副标题会贴住，再松 16:9 机型会露出黑边。

**缩放与安全区互相依赖**：px 安全区要除以 scale 才能变成设计单位，而 scale 又取决于安全区吃掉多少高度。
`R.fit()` 用**迭代法**收敛（最多 5 轮），并且让 `buildLayout` 自己报"我需要多高"（`neededH`），
而不是外部拍一个 1280 常数 —— 后者会让 iPhone 8 白多出 11px 黑边，迭代后只剩 1.6px。

浏览器里想肉眼验收，用 preview 的 `wx-` 前缀（模拟 iPhone 13 的实测值，把系统 UI 画成参考框）：

```
tools/preview.html#wx-full     # 微信安全区下的中局
tools/preview.html#wx-menu     # 微信安全区下的菜单
```

## 二、跑起来

### 微信小游戏（正式方式）

1. 打开「微信开发者工具」→ 新建项目 → 选择**小游戏**。
2. 目录选择本文件夹（`echo-defense`）。
3. AppID 填你自己的，或直接点「测试号」。
4. 编译即可。入口是 `game.js`，配置在 `game.json`。

> `project.config.json` 里的 `appid` 已填 `wx87df6e7090417232`，换成你自己的即可。
> 注意 `setting.es6` 是 `false` —— 代码全部按 **ES5** 写（不用箭头函数 / let / const / 模板字符串），
> 在关闭转换的情况下也能直接编译。改代码时请保持这条约束。

### 浏览器预览（调试用）

直接用浏览器打开 `index.html` 就能玩，同一套逻辑代码，只是把 `wx.*` 换成了 DOM 事件。
手机浏览器建议开「添加到主屏幕」全屏体验。

### 无头自检（改完数值先跑一遍）


### 启动路径自检（改动 `runtime.js` / `main.js` 或渲染入口后必跑）

**这条覆盖的是最容易漏的一块盲区**：逻辑自检和截图页都跑不到 `boot() → bindInput() → 主循环`
这条真实启动链路，而浏览器端最致命的错误恰恰只在那里暴露。

```bash
"$CHROME" --headless=new --no-sandbox --dump-dom \
  "file://$PWD/tools/boot-selftest.html" | grep -o '{"steps".*}' | head -1
```

或直接用浏览器打开 `tools/boot-selftest.html`。依次断言：模块加载 → **`raf` 可调用** →
`boot()` → 六条输入命中路径 → 120 帧主循环 → 建造/脉冲/回声倒带。全同步执行，不依赖定时器。

> ### 它真的抓到过东西
>
> 最初 `runtime.js` 里写的是 `R.raf = requestAnimationFrame`，然后 `main.js` 用 `R.raf(step)` 调用。
> 这看起来完全正常，**但在浏览器里必崩**：以 `R.raf(...)` 形式调用时 `this` 变成了 `R` 这个普通对象，
> Chrome 会抛 `TypeError: Illegal invocation`。
>
> 后果是**浏览器版主循环第一帧就挂，游戏完全跑不起来** —— 而无头逻辑自检（走固定步长、不碰 rAF）
> 和截图页（只做同步 update + 一次 draw）**全都是绿的**。
>
> 修法是包一层，让 `requestAnimationFrame` 以裸名调用：
>
> ```js
> R.raf = (typeof requestAnimationFrame === 'function')
>   ? function (cb) { return requestAnimationFrame(cb); }   // this 为 undefined，合法
>   : function (cb) { return setTimeout(function () { cb(Date.now()); }, 16); };
> ```
>
> **教训**：调用外部宿主函数时，别把函数引用直接挂到自己的对象上再以方法形式调用。
> 同理适用于 `wx.*` 系列 API。

## 四、想改数值改哪里

几乎全部集中在 `js/config.js`：

- `CFG.TOWERS` —— 上场六座塔（一元素一座）的价格、伤害、射程、攻速、耐久、攻击方式；
  冰塔「凝霜」的定义在同一处用注释块留档
- `CFG.TOWER_ORDER` —— **哪几座塔上场、卡片按什么顺序铺**（两行排布由它算出来；
  冰塔就是在这里被注释掉的）
- `CFG.ELEM` —— 七元素的名称与配色（图标形状在 `js/icons.js`）。元素与上位与否无关，七种全留档
- `CFG.LV` —— 每级成长率
- `CFG.RES.reactions` —— **20 组元素反应**的全部参数（key 按元素名字母序拼接，如 `cryo|pyro` = 融化）
- `CFG.ECHO` —— 回声的充能速度、回溯窗口、后遗症强度
- `CFG.ENEMIES` —— 敌人血量/速度/护甲/拆塔 DPS 与**主色**（形象本身在 `js/monsters.js`，
  **加一只怪要动三个文件**：这里给数值、`monsters.js` 给形象、`codex.js` 给档案文案；
  漏了第三处，图鉴里那一格会是空的 —— `layout-check.js` 的「图鉴覆盖全部怪物」会报出来）
- `CFG.MON_EXTENT` —— 形象外扩登记值（`r` 的倍数），弹窗的纵向排布按它算。
  改了形象让它长得更高，自检会要求同步更新这个值，别手改除非确实量过
- `CFG.START_ENERGY / PREP_TIME / TOTAL_WAVES` —— 节奏与难度
- `CFG.VIS` —— 表现层开关：子弹拖尾、冷却环、共振链流光速度、伤害飘字下限

音效的音色与音量在 `js/audio.js` 的 `LIB` 里，每个音效就是一个函数体；
节流阈值在同文件的 `GATES` 表。**整体响度只改两个常数**：`MASTER_VOL`（压缩前电平）
与 `MAKEUP_VOL`（压缩后补偿），改完跑 `tools/audio-selftest.html` 验证。

布局相关的都在 `js/config.js` 的 `CFG.buildLayout`：
HUD 各行的纵向位置、`k`（微信下的纵向压缩比）、`gapY`（HUD 与棋盘的间距）、
方案 A/B 的切换阈值、**建造栏的两行卡片几何**（`gap`/`cardH`/`perRow` 一处改全会跟着走：
栏高由卡片算出来，不再是一个常数）。安全区数值本身来自 `js/runtime.js` 的 `syncInsets()`。

元素图标是矢量路径，换/加元素只需在 `js/icons.js` 的 `SRC` 里补一条 `{ vb, d }`
（`d` 就是 SVG 的 path 数据），卡片、塔身核心会自动跟着变。

难度的主要旋钮在 `js/waves.js` 的 `hpMul`：
`1 + A*(n-1) + B*(n-1)^2`，A 管前中期斜率，B 管后期陡度。

改完跑一次 `node tools/simulate.js 400000`，看逐波记录里核心血量的下降曲线是否合意。

## 五、已知边界

- 一次性挂在屏幕上的敌人上限为 72，超出会推迟刷怪（防止低端机掉帧）。
- 共振网络每 0.22 秒重算一次，不是逐帧；因此塔被拆后反应节点最多延迟 0.22 秒消失。
- 回退快照每 0.15 秒一个对象、保留 27 个，属于可控的 GC 压力；若要压得更狠可改成定长 TypedArray。
- 特效总量上限 1100，超出丢最旧的；实测三种经济强度下峰值 238~313。
- **音效需要基础库 2.19.0+**（`wx.createWebAudioContext`）。更低版本会自动静音，功能不受影响。
- **安全区需要基础库 2.1.0+**（`wx.getMenuButtonBoundingClientRect`）。取不到胶囊时
  `capsuleLeft/Bottom` 归零，右列退回浏览器那套位置 —— 顶部仍会按状态栏高度让开，只是不再避让胶囊。
- 16:9 屏幕（iPhone 8 / SE、360×640 安卓）装了状态栏后设计区高度不够，会**等比缩小并左右各留 1.6~4.4px 黑边**。
  这是刻意的降级：棋盘 832px 是固定尺寸，缩格子会改变塔的射程与格子数的关系，从而影响平衡。
- 建造栏的栏高不是常数，由卡片几何算出（`cardPadTop` × 2 + `cardH` × 2 + `rowGap` = 236）。
  它比更早那版「一行 9 张」的 164 高 72，短屏机型（16:9）的整体缩放因此小了约 5%
  （高屏机型高度有富余，缩放一点不动）。**注意：减少卡片张数省不了高度** —— 只要还是两行，
  栏高就还是 236。想回收高度只能减 `cardH`，但卡内三行文字会先撞上，跑 `layout-check.js` 会立刻报。
- **七元素图标是一套第三方矢量图标**（`js/icons.js` 里是 SVG 的 path 数据，取自社区镜像仓库
  [Sacr3d/genshin-icons](https://github.com/Sacr3d/genshin-icons) 提取的 `Elements/SVG`）。
  这些图形不是本项目原创、版权归原权利方，仓库链接只作为来源与授权状态的说明：
  **要商业化就得换成自己的图标** —— 在 `SRC` 里把对应那条的 `d` 换掉即可，其余代码一行不用动。
- **怪物形象是这个项目自己画的原创矢量角色**（`js/monsters.js`），不含任何第三方素材，
  也没有图片文件 —— 唯一的第三方资产就是上面那七个元素图标。
- **图鉴的解锁记录只能往前长**：`echo_seen` 一旦写入就不会自己回收，也没有「重置图鉴」的入口
  （重置等于把玩家的收藏删了，不该给按钮）。想重看首次遭遇弹窗，只能在开发者工具里清掉这个键。
- **图鉴的反应块按 6 行预留**（`UI.CODEX_REACT_H`）。当前最"多反应"的元素是风/岩（各 6 条），
  正好占满；若以后给某元素加到第 7 条反应，自检的「元素反应条数 ≤ 6」会先报出来，
  那时得连块高和 `CODEX_H` 一起调 —— 别只改数据。
