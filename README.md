# 回声防线 · ECHO LINE

一个**故意不像传统塔防**的微信小游戏。纯 Canvas 2D 绘制，无任何外部图片/音频资源，整个包体就是 JS。

---

## 一、它哪里不一样

| 传统塔防 | 回声防线 |
|---|---|
| 敌人沿固定路线走，塔只管输出 | **塔会占格变成墙，敌人用流场实时重算路线绕开你** —— 你其实是在边打边造迷宫 |
| 把路堵死就赢了 | 完全封死时，敌人会**转身直接拆你的塔** |
| 塔之间毫无关系，堆满就行 | **元素共振**：同元素相邻成链加伤，异元素相邻触发三种反应 |
| 漏怪只能干看着 | **回声倒带**：充能满可让整个战场回退 4 秒（含已漏掉的怪、已花掉的钱） |
| 塔只能升级 | 额外有**主动技「共振脉冲」**：手动点地板放范围伤害＋眩晕 |
| 只有静态贴图 | **22 种程序化合成音效 + 16 类特效**：爆闪、冲击波、分叉电弧、冰晶、顿帧、屏幕暗角 |

### 1. 会绕路的敌人（动态迷宫）

地图上没有预置路径。每当你落下一座塔，全场的 BFS 流场立刻重算，
所有敌人的行进方向当帧改变。

- 入口在左上 / 右上，核心在正下方正中（两格宽）。
- 敌人沿「到核心的 BFS 距离场」逐格下降，支持斜向走位但禁止穿墙角。
- 若流场显示**完全不可达**，敌人自动切换为「拆塔模式」，奔向最近的塔并造成持续伤害。
- 因此龟缩封路不是必胜策略，而是一场「用空间换时间」的赌博。

### 2. 元素共振（本作核心玩法）

三种元素：**赤炎 / 寒霜 / 雷引**。

**同元素相邻 → 共振链**
链内每座塔都获得加成：链长 n 时伤害 ×(1+0.16(n−1))、攻速 ×(1+0.08(n−1))（n 封顶 7）。
链在视觉上表现为塔之间流动的虚线。

**异元素相邻 → 反应节点**
在两塔交界处生成一个自动触发的节点，有独立冷却环：

| 组合 | 反应 | 效果 |
|---|---|---|
| 赤炎 + 寒霜 | 汽爆 | 78 半径范围伤害 + 沿行进反方向击退 |
| 寒霜 + 雷引 | 超导 | 范围减速 50%，并施加「易伤」+25% 承受伤害 |
| 赤炎 + 雷引 | 过载 | 闪电链跳跃最多 4 个目标 |

> 这就是本作的解题核心：**想拉满伤害要同元素抱团，想吃到反应又必须让异元素贴边。**
> 两种需求互相拉扯，摆位本身成了策略。

### 3. 回声倒带

每 0.15 秒对全场（敌人位置与血量、塔的等级与耐久、能量、分数）做一次快照，环形缓冲保留 4 秒。
充能满 100% 时点击「回声倒带」，整个战场回溯 4 秒 —— 包括**已经漏掉的怪会被拉回来重新走一遍**。

代价是：回声清空，并且所有敌人获得 +18% 移速持续 5 秒（"适应"）。

### 4. 敌人图鉴

| 单位 | 行为 |
|---|---|
| 游荡体 | 基础单位 |
| 疾行体 | 高速低血 |
| 装甲体 | 高血、有护甲（平砍减免） |
| 破墙者 | **专程绕过防线去拆塔**，不追核心 |
| 相位体 | 周期性进入相位态，**无视你的墙直接穿过去** |
| 共鸣吞噬者（Boss） | 靠近时**压制范围内所有塔，使其脱离共振网络** |

### 5. 音效与特效

**音效全部是实时合成的**，一个音频文件都没有，所以包体不会变大。

- 每个音效 = 若干个振荡器 + 一段滤波噪声，现场叠加包络（`js/audio.js`）。
- 三个关键工程点：
  1. **节流**：命中音 48ms、开火音 140ms 内最多 3 声。塔一多就必然重叠，不做预算会变成白噪音。
  2. **压缩器**：主输出挂 `DynamicsCompressor`，几十路音同时响也不会削顶爆音。
  3. **渐进降级**：浏览器走 `AudioContext`（需首次点击解锁），小游戏走 `wx.createWebAudioContext()`；
     两者都不可用时静默无声，绝不影响游戏逻辑。
- 右上角有音效开关，状态存本地，任何界面都能点。

**响度链路**（`master → compressor → makeup → destination`）：

调整音量时最容易踩的坑是把压缩器阈值压得太低。原来的 `-16dB / 9:1` 会把**单个音头也一起削掉**，
听感上不是"变稳"而是整体发闷、变小。现在只拦真正的峰值：

| 参数 | 值 | 说明 |
|---|---|---|
| `MASTER_VOL` | 0.85 | 送进压缩器之前的电平，也是静音开关的目标值 |
| 压缩器阈值 / 比 | -10dB / 5:1 | 只压峰值，不碰正常音头 |
| `MAKEUP_VOL` | 1.30 | 压缩之后再补回来 |

整体响度比调整前高约 2.5 倍（单音头从 ~0.165 提到 ~0.42）。**要整体调响或调轻，只动那两个常数**，
`audio-selftest.html` 里有断言锁住它们，改小会被自检挡下。

**特效分两个绘制层**（`js/fx.js`）：

- `glow` 层用 `lighter` 叠加混合 → 冲击波、电弧、光束、爆闪、炮口闪光
- `solid` 层用常规混合 → 粒子、碎片、余烬、飘字

每帧只切换两次合成模式，所以哪怕同时几百个特效也不掉帧。特效总量有 1100 的上限，
超出会丢弃最旧的一批（实测高负载峰值约 300）。

**炮塔视觉**：六边形底盘 + 可见的**冷却环**（走完一圈就是一次开火，节奏一眼看清）、
伸到底盘外的炮管、开火后坐、三种元素三种管口形状、底部等级刻度、
被 Boss 压制时跳短路电弧、共振链外环随链长发光。

### 6. 微信安全区适配（状态栏 / 胶囊 / home 指示条）

小游戏里 canvas 是**铺满全屏**的，状态栏、右上角胶囊、home 指示条都浮在它上面：
画上去的内容会被盖住，**胶囊还会吞掉那块区域的点击**。所以这三个区域必须主动让开。

适配的真值来自两个 API，缺一不可：

| 来源 | 用途 |
|---|---|
| `wx.getWindowInfo().statusBarHeight` | 顶部整宽留白（时间 / 信号那条） |
| `wx.getWindowInfo().safeArea` | 底部 home 指示条留白 |
| `wx.getMenuButtonBoundingClientRect()` | **胶囊的精确矩形**。不能猜，各机型差别很大 |

三个设计决定：

1. **左右两列分开处理**。状态栏占满整宽，左对齐内容（标题、血条）只要躲开它；
   右对齐内容（波次、最高分、能量）还得再躲开胶囊。
2. **右列优先"并排缩到胶囊左侧"，而不是整体下移**。顶部纵向空间是稀缺资源，
   下移会把开波按钮和棋盘一起推下去，16:9 机型直接排不下。
   胶囊左沿留出 14 设计 px 余量 → 方案 A。
   只有当这个位置挤到 490 以下（会撞上血条），才退回"整列下移到胶囊之下" → 方案 B。
3. **音效开关挂在胶囊正下方**。那块是天然空档，且离系统按钮最近，手感最顺。

HUD 在微信下按 **0.86** 纵向压缩（浏览器保持 1.0，逐像素不变），把省下的高度还给棋盘。
`0.86` 是量出来的：再紧标题与副标题会贴住，再松 16:9 机型会露出黑边。

**缩放与安全区互相依赖**：px 安全区要除以 scale 才能变成设计单位，而 scale 又取决于安全区吃掉多少高度。
`R.fit()` 用**迭代法**收敛（最多 5 轮），并且让 `buildLayout` 自己报"我需要多高"（`neededH`），
而不是外部拍一个 1280 常数 —— 后者会让 iPhone 8 白多出 11px 黑边，迭代后只剩 1.6px。

浏览器里想肉眼验收，用 preview 的 `wx-` 前缀（模拟 iPhone 13 的实测值，把系统 UI 画成参考框）：

```
tools/preview.html#wx-full     # 微信安全区下的中局
tools/preview.html#wx-menu     # 微信安全区下的菜单
```

## 二、跑起来

### 微信小游戏（正式方式）

1. 打开「微信开发者工具」→ 新建项目 → 选择**小游戏**。
2. 目录选择本文件夹（`echo-defense`）。
3. AppID 填你自己的，或直接点「测试号」。
4. 编译即可。入口是 `game.js`，配置在 `game.json`。

> `project.config.json` 里的 `appid` 已填 `wx87df6e7090417232`，换成你自己的即可。
> 注意 `setting.es6` 是 `false` —— 代码全部按 **ES5** 写（不用箭头函数 / let / const / 模板字符串），
> 在关闭转换的情况下也能直接编译。改代码时请保持这条约束。

### 浏览器预览（调试用）

直接用浏览器打开 `index.html` 就能玩，同一套逻辑代码，只是把 `wx.*` 换成了 DOM 事件。
手机浏览器建议开「添加到主屏幕」全屏体验。

### 无头自检（改完数值先跑一遍）

```bash
node tools/simulate.js 400000          # 常规经济 AI 跑 40 万帧
node tools/simulate.js 400000 --rich   # 无限经济，验证上限
node tools/simulate.js 400000 --rich --seal   # 全图封死，验证「拆塔」分支
```

会输出逐波记录（每波后的核心血量 / 漏怪 / 击杀 / 塔数 / 链数 / 节点数）、
特效帧数与峰值，并在出现异常、NaN 坐标、波次推进失败时以非 0 退出码报错。
`tools/` 已在 `project.config.json` 的 `packOptions.ignore` 中排除，不会进包。

### 启动路径自检（改动 `runtime.js` / `main.js` 或渲染入口后必跑）

**这条覆盖的是最容易漏的一块盲区**：逻辑自检和截图页都跑不到 `boot() → bindInput() → 主循环`
这条真实启动链路，而浏览器端最致命的错误恰恰只在那里暴露。

```bash
"$CHROME" --headless=new --no-sandbox --dump-dom \
  "file://$PWD/tools/boot-selftest.html" | grep -o '{"steps".*}' | head -1
```

或直接用浏览器打开 `tools/boot-selftest.html`。依次断言：模块加载 → **`raf` 可调用** →
`boot()` → 六条输入命中路径 → 120 帧主循环 → 建造/脉冲/回声倒带。全同步执行，不依赖定时器。

> ### 它真的抓到过东西
>
> 最初 `runtime.js` 里写的是 `R.raf = requestAnimationFrame`，然后 `main.js` 用 `R.raf(step)` 调用。
> 这看起来完全正常，**但在浏览器里必崩**：以 `R.raf(...)` 形式调用时 `this` 变成了 `R` 这个普通对象，
> Chrome 会抛 `TypeError: Illegal invocation`。
>
> 后果是**浏览器版主循环第一帧就挂，游戏完全跑不起来** —— 而无头逻辑自检（走固定步长、不碰 rAF）
> 和截图页（只做同步 update + 一次 draw）**全都是绿的**。
>
> 修法是包一层，让 `requestAnimationFrame` 以裸名调用：
>
> ```js
> R.raf = (typeof requestAnimationFrame === 'function')
>   ? function (cb) { return requestAnimationFrame(cb); }   // this 为 undefined，合法
>   : function (cb) { return setTimeout(function () { cb(Date.now()); }, 16); };
> ```
>
> **教训**：调用外部宿主函数时，别把函数引用直接挂到自己的对象上再以方法形式调用。
> 同理适用于 `wx.*` 系列 API。

### 音效自检（改动 `audio.js` 后跑）

音效没法用眼睛验收，所以有一个在真实浏览器里把 22 个音色全部播一遍的页面：

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CHROME" --headless=new --no-sandbox --autoplay-policy=no-user-gesture-required \
  --virtual-time-budget=8000 --dump-dom \
  "file://$PWD/tools/audio-selftest.html" | grep -o '{"ok".*}' | head -1
```

或直接用浏览器打开 `tools/audio-selftest.html`。它会验证四件事：

1. `AudioContext` 能否建立、22 个音色是否全部播放且零异常
2. **节流**：同名音连打 6 次只放行 1 次
3. **开火预算**：三种开火音混合连打 9 次只放行 3 次
4. **静音**：静音后必须彻底无声，取消静音后恢复

### 安全区适配自检（改布局 / `runtime.js` / `config.js` 后跑）

状态栏、胶囊、home 条只在真机上存在，浏览器里跑不出来，所以直接喂假系统信息给 `runtime`：

```bash
node tools/layout-check.js
```

它用 9 个机型档案（浏览器 / iPhone 13 / iPhone 16 Pro / iPhone 8 / iPhone SE /
Android 360×800 / Android 360×640 / Android 412×915 / iPad）各建一次布局，
逐条断言 18 项，其中最关键的四类：

1. **不压状态栏**：标题、血条、波次文字、开波按钮的顶边都在状态栏之下
2. **不压胶囊**：音效开关整个在胶囊下方；右对齐列的包围盒与胶囊矩形**无交集**
3. **不压 home 条**：建造栏底边在安全线之上
4. **顺序正确**：HUD → 棋盘 → 建造栏依次排开，且棋盘完整落在两者之间

外加一条回归护栏：安全区带来的额外横向留边不得超过 4%（实测 16:9 机型只有 1.6~4.4px）。

### 界面截图（调布局后跑）

```bash
for m in menu game panel fx full over; do
  "$CHROME" --headless=new --no-sandbox --hide-scrollbars --force-device-scale-factor=2 \
    --window-size=500,1100 --virtual-time-budget=6000 \
    --screenshot="/tmp/$m.png" "file://$PWD/tools/preview.html#$m"

```

`#fx` 会把新增特效一次性摊开，专门用来验收渲染效果；
`#wx-full` / `#wx-menu` 会模拟微信安全区并把状态栏、胶囊、home 条画成参考框，用来验收顶部适配。

> **无头截图有个坑**：`--window-size` 不等于视口。实测本机 Chrome（`--headless=new`）在
> `--window-size=500,1100` 下视口是 **500×1013**（高度少 87px，视口宽度另有 500px 下限）。
> 所以 `--screenshot` 出来的图是按视口渲染的，直接按 `window-size × dpr` 裁会**切掉底部**，
> 看起来像布局崩了，其实是截图参数的锅。先用 probe 页量准视口再裁。

## 四、想改数值改哪里

几乎全部集中在 `js/config.js`：

- `CFG.TOWERS` —— 三种塔的价格、伤害、射程、攻速、耐久
- `CFG.LV` —— 每级成长率
- `CFG.RES` —— 共振链增益系数与三种反应的全部参数
- `CFG.ECHO` —— 回声的充能速度、回溯窗口、后遗症强度
- `CFG.ENEMIES` —— 敌人血量/速度/护甲/拆塔 DPS
- `CFG.START_ENERGY / PREP_TIME / TOTAL_WAVES` —— 节奏与难度
- `CFG.VIS` —— 表现层开关：子弹拖尾、冷却环、共振链流光速度、伤害飘字下限

音效的音色与音量在 `js/audio.js` 的 `LIB` 里，每个音效就是一个函数体；
节流阈值在同文件的 `GATES` 表。**整体响度只改两个常数**：`MASTER_VOL`（压缩前电平）
与 `MAKEUP_VOL`（压缩后补偿），改完跑 `tools/audio-selftest.html` 验证。

布局相关的都在 `js/config.js` 的 `CFG.buildLayout`：
HUD 各行的纵向位置、`k`（微信下的纵向压缩比）、`gapY`（HUD 与棋盘的间距）、
方案 A/B 的切换阈值。安全区数值本身来自 `js/runtime.js` 的 `syncInsets()`。

难度的主要旋钮在 `js/waves.js` 的 `hpMul`：
`1 + A*(n-1) + B*(n-1)^2`，A 管前中期斜率，B 管后期陡度。

改完跑一次 `node tools/simulate.js 400000`，看逐波记录里核心血量的下降曲线是否合意。

## 五、已知边界

- 一次性挂在屏幕上的敌人上限为 72，超出会推迟刷怪（防止低端机掉帧）。
- 共振网络每 0.22 秒重算一次，不是逐帧；因此塔被拆后反应节点最多延迟 0.22 秒消失。
- 回退快照每 0.15 秒一个对象、保留 27 个，属于可控的 GC 压力；若要压得更狠可改成定长 TypedArray。
- 特效总量上限 1100，超出丢最旧的；实测三种经济强度下峰值 238~313。
- **音效需要基础库 2.19.0+**（`wx.createWebAudioContext`）。更低版本会自动静音，功能不受影响。
- **安全区需要基础库 2.1.0+**（`wx.getMenuButtonBoundingClientRect`）。取不到胶囊时
  `capsuleLeft/Bottom` 归零，右列退回浏览器那套位置 —— 顶部仍会按状态栏高度让开，只是不再避让胶囊。
- 16:9 屏幕（iPhone 8 / SE、360×640 安卓）装了状态栏后设计区高度不够，会**等比缩小并左右各留 1.6~4.4px 黑边**。
  这是刻意的降级：棋盘 832px 是固定尺寸，缩格子会改变塔的射程与格子数的关系，从而影响平衡。
- 顿帧（`hitStop`）只在渲染主循环里生效，无头模拟走固定步长，所以**改音效/特效不会影响平衡测试结果**。
- 部分安卓机对 `globalCompositeOperation = 'lighter'` 有性能开销，若在真机上发现掉帧，
  可把 `fx.js` 里 `GLOW_TYPE` 中的项逐个移出，让它们走常规混合层。
